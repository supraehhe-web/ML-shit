# Arm C diagnosis, second pass: undertrained, trained wrongly, or a broken sampler?

Generated by `scripts/27_build_diagnosis_v2.py` from the artifacts named in each section. Validation synthetic pairs only: no test image, label, mask or metric was read to reach any conclusion here. Thresholds and rules were pre-registered in `reports/decision_log.md` (D22, D23, D24) before the corresponding jobs ran.

## Summary

The first diagnosis (D19) concluded "undertrained" from an identity test that used the *released* checkpoint. That test can only show that the inference path works for weights that work; it cannot detect a defect in our own training. Re-examining the trainer found one, and the retrained model still fails the validity gate, so the honest state is: **the first checkpoint was trained wrongly, and the corrected retrain is still not good enough to serve as a confirmatory DM-AHR arm.**

| Question | Answer | Evidence |
|---|---|---|
| Was the first trainer faithful to upstream? | **No.** It fed the denoiser `t/T`; upstream trains and samples with the continuous level sqrt(alpha_bar). | `src/dm_ahr_vit/diffusion/conditioning.py`, `tests/test_diffusion_conditioning.py` |
| Was there an EMA or sampling-weights bug? | **No.** Upstream marks `ema_scheduler` "not used now" and no EMA code exists in any upstream Python file, so no EMA weights exist to load. | `artifacts/logs/dermahair_sample_audit.json` |
| Did the corrected retrain fix it? | **No.** It improves PSNR from 13.9 to 17.2 dB but stays below the pre-registered gate of hairy + 3 dB (25.3 dB). | `arm_c_v2_scores.json` |
| Is the short sampler sound? | **No, not as first written.** Re-deriving a linear schedule over a shorter chain ends at a different final noise level. A respaced sampler fixes that. | `tests/test_respacing.py`, `arm_c_v2_respaced.json` |
| Can the released checkpoint serve as a DM-AHR arm? | **Yes, as an exploratory arm.** It passes the validity gate at 25 respaced steps. | `arm_c_v2_respaced.json` |

## 1. Static audit of the trainer against upstream

| Item | Upstream | This repository, first version | This repository, now |
|---|---|---|---|
| Denoiser conditioning | continuous sqrt(alpha_bar), drawn uniformly in [prev[t-1], prev[t]] | `t / T` (a value rising 0 to 1 while the true level falls 1 to 0) | upstream convention |
| Gradient clipping | none | `clip_grad_norm_(1.0)` | none (matches upstream) |
| Loss | L1 on noise, mean over batch x channels x pixels | same | same |
| Optimiser | Adam, lr 1e-4 | same | same |
| EMA | config field marked "not used now"; no code | none | none |
| Sampling weights | raw `state_dict` | raw `state_dict` | raw `state_dict` |

The conditioning mismatch is the substantive difference. It is not a cosmetic detail: the denoiser is asked at sampling time for the noise at level sqrt(alpha_bar), and the first trainer never showed it that quantity.

## 2. Noise-prediction error (validation pairs)

Identical noisy inputs, 100 validation pairs, timesteps [200, 800, 1400, 1900]; only the value handed to the denoiser differs between the two columns.

| Checkpoint | MSE under upstream conditioning | MSE under `t/T` conditioning |
|---|---|---|
| ours | 0.04217 | 0.00078 |
| ours_fixed | 0.00077 | 0.04137 |
| released | 0.00447 | 0.04955 |

- The first checkpoint is 54.1x worse under the conditioning its sampler uses than under the one its trainer used.
- The released checkpoint shows the opposite pattern, 11.1x worse under `t/T`.
- The retrained checkpoint matches upstream (prefers upstream = True).

**Limitation of this test, stated plainly.** At high timesteps the noisy input is almost pure noise, so a model that simply copies its input scores well regardless of conditioning. The absolute MSE values are therefore not interpretable as model quality; only the *within-checkpoint comparison between the two conditioning values* is, because the input and the target are identical in both columns. The test is also not independent evidence of the bug: the bug was found by reading the code, and this test confirms its signature.

## 4. Noise versus blur, measured against the hairy input

The first diagnosis compared our output's high-frequency energy with the *hairless reference* and reported "about 15x". That comparison was misleading, because the hairy input itself already carries 4.97x the reference's high-frequency energy. Measured against the hairy input, which is the honest baseline:

- **released:** HF energy 0.60x the hairy input, noise sigma 0.69x the hairy input.
- **ours_legacy_trainer:** HF energy 2.87x the hairy input, noise sigma 19.68x the hairy input.
- **fixed_5000:** HF energy 0.93x the hairy input, noise sigma 5.98x the hairy input.
- **fixed_10000:** HF energy 1.12x the hairy input, noise sigma 7.34x the hairy input.
- **fixed_15000:** HF energy 1.04x the hairy input, noise sigma 6.66x the hairy input.
- **fixed_20000:** HF energy 0.64x the hairy input, noise sigma 4.01x the hairy input.

So the first checkpoint's output was **noisier than the hairy input it was given** (2.9x the high-frequency energy, 19.7x the noise sigma), which is the opposite of blur. The retrained checkpoint is quieter than the hairy input but still carries about 4x its noise sigma, and its PSNR is below the hairy input's, so it is not a usable restoration either. The word "over-smoothed" was wrong for both, and is withdrawn.

## 5. Warm start and overfit tests

| Trainer | Pre-fine-tune L1 | Mean L1, last 100 iterations | Ratio | Loss jump (>1.5x)? |
|---|---|---|---|---|
| legacy | 0.1420 | 0.0202 | 0.142 | False |
| upstream | 0.0292 | 0.0168 | 0.575 | False |

Neither trainer shows a loss jump when fine-tuning the released weights, so this test did **not** discriminate between them. It is reported as inconclusive rather than as support for either branch. The reason is visible in the numbers: the released checkpoint is already at a low loss under both conditioning values, so 500 iterations of fine-tuning cannot produce a large enough jump to detect.

**Overfit test:** 8 training pairs, 2,000 iterations, then sampled at 1000 steps. Mean PSNR 14.54 against a hairy-input baseline of 21.85 (margin -7.31 dB, required +3). **Passed = False.**

This test is **not evidence about the trainer**, because it sampled with the re-derived short schedule that section 6 shows to be broken. It needs a rerun with the respaced sampler before it can be read either way.

## 7. What this means for the study

1. **The first Arm C is a failed reproduction, not a test of DM-AHR.** It was trained with a conditioning bug and sampled with a mismatched schedule. It moves to an appendix and out of the confirmatory family.
2. **The corrected retrain is still not a valid DM-AHR arm.** It fails the pre-registered validity gate, so the confirmatory DM-AHR comparisons (A vs C-fixed, B vs C-fixed) are reported as **untested**, and the confirmatory Holm family keeps its pre-registered size of 3.
3. **The released checkpoint is a valid, exploratory DM-AHR arm.** It passes the gate at 25 respaced steps. It is labelled exploratory because its training data are undocumented and the paper states that HAM10000 images outside its 700-image test set were used for training, so it has very likely seen this study's clean validation and test images. No independence claim is made for it.
4. **H1 and H2 for DM-AHR are tested only through the exploratory arm.** Their verdicts are stated from that arm alone, with the independence caveat attached.
5. **The iteration framing is corrected.** The first Arm C was trained at 20,000 iterations, the paper's stated count, which is about 3% of the released checkpoint's 725,000. The paper's text and its own release disagree; that is a fact about the paper, not a budget excuse for this study. "Under-resourced versus the paper" is withdrawn.

## 8. What is still open

- **Why the corrected retrain still fails is not established.** The conditioning bug is fixed and the noise-prediction error now matches upstream, yet sampled quality stays below the hairy input. Candidates not yet tested: the synthetic-hair pairs may be too few or too uniform for 20,000 iterations; the L1-on-noise objective with a 64-channel UNet may need the paper's full schedule; the 128 px training resolution may be too low for the hair structures. Distinguishing these needs another retrain, which the remaining budget does not cover.
- **The overfit test must be rerun with the respaced sampler** before it can be read.
- **The warm-start test did not discriminate** and is reported as inconclusive.
- **The paper's own hairy-input floor is not reported**, so the paper's 41.04 dB cannot be placed against a no-model baseline. See `reports/paper_reproduction.md`.
